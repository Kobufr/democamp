# リアルの記録・3D体験・気になる（試作）

ブランチ: `feat/real-camp-memories-trial`

## 試す操作

1. 地図でキャンプ場を選ぶ。「行った記録をつける」から、キャンプ場・日付を確認して保存。3D体験は不要。
2. 日付は正確な開始・終了日、年月だけ、日付不明を選べる。終了日が空欄なら日帰り。
3. 写真を3枚まで追加し、ひとことを記入。「もう少し詳しく残す」で区画名、同行者、天気、次回メモ、実際の装備を追加。
4. 装備は複数選択。最初はチェックせず、「持っていく装備を候補に入れる」で現在の選択を候補にできる。記録時の名前・色・形を保存するため、後のガレージ変更には追従しない。
5. キャンプ場の「思い出・詳細」には思い出・3D体験・気になるの3タブ。3D体験はリアルの訪問数を増やさない。リアルで行った場所も「気になる」を併用できる。
6. ヘッダーの「マイジャーナル」で写真付き思い出一覧、3D体験履歴、気になる一覧を切り替える。
7. 思い出の編集・削除・復元に対応。「最近削除した記録」から復元。削除しても3Dの進行は変わらない。

## 保存

- `records[campId].memories` がリアルの記録、既存の `visits` が3D体験、`wishlist` / `wishlistNote` が気になると理由。
- 既存のゲーム履歴や手動履歴を、自動でリアルの記録に変換しない。
- 既存のアカウントごとのD1保存・端末保存・同期を使用。テーブル追加やマイグレーションは不要。
- 別端末との競合は思い出IDと更新日時で統合。削除フラグを保存するので、古い端末の記録が削除を取り消さない。同日・同じキャンプ場でも独立した記録を持てる。
- 写真は端末で縮小したJPEGのみを保存。1枚50,000文字以下、3枚まで。全体の写真データは1,500,000文字まで。元の画像やEXIFは保存しない。試作は写真の原本保管を目的としない。
- 思い出は全体500件、キャンプ場ごと200件まで。APIは写真・日付・枚数・ID・データ容量を検証する。
- 写真の大容量保存とリアル記録からの3D再現は次の段階。試作で3Dを自動再現したり、実際に行ったと推測して保存したりはしない。

## 検証

日付・宿泊・日帰り・年月・不明、実際の記録と3Dの分離、併用可能な気になる状態、更新/削除/復元の競合統合、装備複数選択のスナップショット、写真の制約、表示時のエスケープを自動テストで確認する。
